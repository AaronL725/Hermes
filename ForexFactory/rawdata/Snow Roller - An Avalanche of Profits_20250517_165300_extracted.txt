Regarding the do Opposite feature if the markets are more rangebound this will tend to perform better. If the markets trend doOpposite = false should do best. I've been going over what is to be learned from the different results from SnowRoller (SR) and SR_Classic. SR_Classic logic: (outline) Inserted Code Determine global trend for a particular symbol. Close(50) - Close(100) on 5 min bars = 250min - 500 min, approx 4 hr - 8hr. Allow taking trades only in the direction of the global trend. Add up trades every buysellstep (5) pips up or down and allow overlapping positions Take off trades the same way when the "trend" shifts from up to down and we are long (for instance) Use CloseThis to bank a large move in single symbol equity Use CloseAll to bank a moderate move in global system equity Current SnowRoller (SR) logic: (outline) Inserted Code Set start point - arbitrarily start with a buy or sell based on last up/down move only take buys above the highest position + buysellstep pips (5) only take sells below the lowest position - buysellstep pips (5) If position is LONG and price goes below the lowest buy by reversallevel # of pips, close all longs. This last item has the effect of a negative equity pop, aka an equity poop. This creates a negative equity drag that is hard to overcome. If we could design the strategy in reverse to take advantage of equity poops there would be a strong upward pull on equity/balance over time. The drawback is the assumption of ASSYMETRICAL RISK. &lt;-- no small thing. Current SR continued Inserted Code CloseAll and CloseThis as in SR_Classic but with percent instead of $$$ Uses a per-position stop that bleeds the account Exit Worst is not a good idea as this also bleeds the account

Here are my ideas for going forward in developing the current version (SnowRoller.mq4) into a fusion of the best parts of the classic and of the current version. The best parts of SR_Classic are having an overriding pattern so positions can be accumulated over a period of time, regardless the immediate market direction. This was based on an approximate 4 hr vs 8 hr close price comparison. Gradual exits from the wrong side were made every 5 pips rather than taking a position, having it move against and then banking a large loss on all positions simultaneously. Using a per-position stop loss or profit target (in particular) is probably a bad idea. Exit worst is probably a bad idea. Adding to positions every 5 pips (in a strict grid) is probably a good idea (from a risk management point of view). Allowing taking positions off every 5 pip move (rather than at a strict grid), allows for quicker exiting of positions but still a gradual change from long to short or vice versa.

Yes that's the basic idea. It looks at MaxEquity and creates a global variable named SRMaxEquity. The percentages used in the CloseAll routine draw upon that value and how much equity goes over the highest previous balance. I'm using the terms interchangeably here because MaxEquity is only calculated after a CloseAll routine, or the first time you start up the EA. There is also a way to pop based on balance - if MaxEquity is too far away you can still get a pop when open equity clears balance by the threshold amounts. As an aside in case anyone is wondering, the other global variable SRCloseAll is set to zero by default, and when one of the routines is closing all positions it is set to 1. You can prevent new trades from happening by setting SRCloseAll to 1 (it won't force a close all). When SRCloseAll = 0 normal trading can occur. So short answer yes.

Another idea which may help profitability: Instead of having fixed SL per entry, can you code it to be more dynamic? I don't think dynamic is the right word but... Entry 1 = Buy 1 lot at 1.0090 with SL of 1.0070. Entry 2 = Buy 1 lot at 1.0110 At this point, BE for all open orders = 1.0100. But you were willing to risk $200 originally, so there is no harm keeping that risk. Now we have 2 lots with average price of 1.0100 so to keep original risk, SL for all open orders is 1.0090. Entry 3 = Buy 1 lot at 1.0130 At this point, we have 3 lot with average price of 1.0110. We can now have SL around 1.0103 which is 27 pips from current price and still keep our original risk. The point is to increase the SL of the later entries by using the profit of the earlier ones. This will enable to entries to better withstand minor retraces so that if it continues, the position will have greater leverage which equals more profit. The stops and target work inter-bar so it's by design when you get a big bar. Someone else was asking about this. If you want stops/targets to apply intra-bar then make the changes: (in the start function) before: Inserted Code if(LotMultiplier &lt;1) LotMultiplier = 1; if (Bars != ThisBarTrade ) { ThisBarTrade = Bars; // ensure only one trade opportunity per bar RefreshRates(); EvaluateCloseAll(); if (ClosingAll) return; EvaluateCloseThis(); if (ClosingThis) return(0); EvaluateStopAndTarget(); after: Inserted Code if(LotMultiplier &lt;1) LotMultiplier = 1; EvaluateStopAndTarget(); if (Bars != ThisBarTrade ) { ThisBarTrade = Bars; // ensure only one trade opportunity per bar RefreshRates(); EvaluateCloseAll(); if (ClosingAll) return; EvaluateCloseThis(); if (ClosingThis) return(0); Basically the only change is moving the EvaluateStopAndTarget(); up from within the one trade per bar section to allow it to evaluate every tick. I haven't got a lot of time but if you need it to be a strict SL/TP then this change should do that. I see you're using v1.007. I thought you were using v1.005.
